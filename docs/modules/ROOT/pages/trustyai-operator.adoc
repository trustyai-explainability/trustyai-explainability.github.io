= TrustyAI operator

image::trustyai-operator-architecture.svg[The TrustyAI module operator installs the workload operator, which reconciles the TrustyAI service, LMEval and EvalHub resources]

The TrustyAI Kubernetes Operator aims at simplifying the deployment and management of the xref:trustyai-service.adoc[TrustyAI service], xref:component-lm-eval.adoc[LM-Eval] and xref:component-evalhub.adoc[EvalHub] on Kubernetes and OpenShift clusters by watching for custom resources in the `trustyai.opendatahub.io` API group and managing the deployments, services, and optionally, routes and `ServiceMonitors` corresponding to these resources.

The operator ensures the service is properly configured, is discoverable by Prometheus for metrics scraping (on both Kubernetes and OpenShift), and is accessible via a `Route` on OpenShift. It also sets the network policy posture of everything it deploys; see xref:trustyai-operator-network-policies.adoc[] for what that means in practice.

== What the operator manages

The operator is delivered in two parts. The module operator is installed once per cluster and renders the manifests for the workload operator, which then reconciles the individual resources:

[cols="2,2,3", options="header"]
|===
| Custom resource | Creates | Notes

| `TrustyAIService`
| `Deployment`, `Service`, optional `Route` and `ServiceMonitor`
| The fairness, drift and explainability API described in xref:trustyai-service.adoc[].

| `LMEvalJob`
| One evaluation `Pod` per job
| Benchmark runs driven by xref:component-lm-eval.adoc[LM-Eval].

| `EvalHub`
| API and MCP `Deployment`s with their `Service`s and `Route`s
| The evaluation platform described in xref:component-evalhub.adoc[].
|===

Every one of those workloads is selected by a `NetworkPolicy` the operator owns, so a cluster running with a default-deny baseline still works. The rules are described in xref:trustyai-operator-network-policies.adoc[Network Policies].

== Installation

=== OpenShift installation

Please refer to the xref:installing-opendatahub.adoc[] page.

=== Kubernetes installation

[NOTE]
====
TrustyAI's operator is designed and supported for OpenShift.

Although _not officially supported_, it is however possible to install it on Kubernetes with a few modifications.
====

==== TrustyAI Service

If installing the TrustyAI operator in Kubernetes, you will need to create the secrets necessary for each TrustyAI's service authenticated `Service`.

OpenShift will automatically create the required secrets for you, whereas in Kubernetes you will need to create them manually.

Assuming you have the TrustyAI operator already installed and wanted to install a TrustyAI service, called `$TRUSTYAI_SERVICE` in an already existing namespace `$NAMESPACE`, you'll need to:

. (Optional) If you don't have the certificate and key in a file, you can create them (just an example):
+
[source,shell]
----
openssl req -x509 -newkey rsa:4096 \
  -keyout trustyai.pem \
  -out trustyai.pem \
  -days 365 -nodes \
  -subj "/CN=$TRUSTYAI_SERVICE" \
  -addext "subjectAltName=DNS:$TRUSTYAI_SERVICE.$NAMESPACE.svc,DNS:$TRUSTYAI_SERVICE.$NAMESPACE.svc.local"
----
+
. Create the secrets in the destination namespace, one for each service (`${TRUSTYAI_SERVICE}-tls` and `${TRUSTYAI_SERVICE}-internal`):
+
[source,shell]
----
kubectl create secret tls ${TRUSTYAI_SERVICE}-tls \
  --cert=trustyai.pem \
  --key=trustyai.pem \
  --namespace $NAMESPACE
kubectl create secret tls ${TRUSTYAI_SERVICE}-internal \
  --cert=trustyai.pem \
  --key=trustyai.pem \
  --namespace $NAMESPACE

----

The TrustyAI service can now be created as usual.
